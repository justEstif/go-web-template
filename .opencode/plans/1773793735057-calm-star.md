# Plan: Replace missing.css with Tailwind CSS + DaisyUI (Standalone)

## Goal
Replace the current `missing.css` CDN link with a locally-built `tailwind.css` generated by the Tailwind CSS Standalone CLI + DaisyUI plugin. Restyle all pages (navbar, home, about, contact) using DaisyUI components.

---

## Approach: Standalone CLI (no Node.js)

The Tailwind CSS Standalone binary + `daisyui.mjs` bundle generates a static `tailwind.css` served from `static/css/`. No Node.js or npm needed. Air runs the Tailwind build as part of its `cmd` on every reload.

---

## Step-by-Step Plan

### 1. Download Tailwind CSS Standalone binary

Download the appropriate binary (Linux x64) into the project root:

```bash
curl -sLo tailwindcss https://github.com/tailwindlabs/tailwindcss/releases/latest/download/tailwindcss-linux-x64
chmod +x tailwindcss
```

### 2. Download DaisyUI bundle files

```bash
curl -sLO https://github.com/saadeghi/daisyui/releases/latest/download/daisyui.mjs
curl -sLO https://github.com/saadeghi/daisyui/releases/latest/download/daisyui-theme.mjs
```

### 3. Create `styles/input.css`

Create the `styles/` directory and `styles/input.css`:

```css
@import "tailwindcss";

@source not "./tailwindcss";
@source not "./daisyui{,*}.mjs";

@plugin "./daisyui.mjs";
```

Note: `@source` paths in `input.css` are relative to where the `tailwindcss` binary is run (project root), so `./daisyui{,*}.mjs` correctly excludes the root-level `.mjs` files.

### 4. Create `static/css/` directory

```bash
mkdir -p static/css
```

### 5. Update `.air.toml`

Prepend the Tailwind build to air's `cmd` and add `.css` to watched extensions:

```toml
[build]
  cmd = "./tailwindcss -i styles/input.css -o static/css/tailwind.css --minify && templ generate && go build -o ./tmp/main cmd/web/main.go"
  include_ext = ["go", "tpl", "tmpl", "html", "templ", "css"]
  exclude_dir = ["assets", "tmp", "vendor", "testdata", "migrations", "static"]
```

Key changes:
- `cmd` now runs Tailwind first (with `--minify`), then `templ generate`, then `go build`
- `include_ext` adds `"css"` so changes to `styles/input.css` trigger a rebuild
- `exclude_dir` adds `"static"` to prevent `static/css/tailwind.css` output from triggering another rebuild loop

All other `.air.toml` settings remain unchanged.

### 6. Update `layout.templ`

**File:** `components/layout.templ`

```templ
package components

templ Layout(title string) {
    <!DOCTYPE html>
    <html lang="en" data-theme="light">
    <head>
        <meta charset="UTF-8"/>
        <meta name="viewport" content="width=device-width, initial-scale=1.0"/>
        <title>{ title }</title>
        <link rel="stylesheet" href="/static/css/tailwind.css"/>
        <script src="https://cdn.jsdelivr.net/npm/htmx.org@2.0.8/dist/htmx.min.js"></script>
    </head>
    <body>
        @Navbar()
        <main class="container mx-auto px-4 py-8">
            { children... }
        </main>
    </body>
    </html>
}
```

Key changes:
- `data-theme="light"` on `<html>` activates DaisyUI theming
- CDN link replaced with `/static/css/tailwind.css`
- `<main>` gets `container mx-auto px-4 py-8` for centered layout

## Trade-off Note

Air's `cmd` runs on **every** file change (`.go`, `.templ`, `.css`). This means Tailwind rebuilds on every Go file save too. The Tailwind Standalone CLI is very fast (no Node.js startup cost), so this is acceptable for a dev template. If latency becomes a concern, Tailwind can be moved to a separate `--watch` process.
